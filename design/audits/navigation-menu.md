# HIG audit: navigation menu

Source: [HIG Navigation and search](https://developer.apple.com/design/human-interface-guidelines/navigation-and-search), the section page; its body is rendered by script and could not be read in full, so the rows below apply general navigation guidance and the pages that already back this library ([Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars), [Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)). Keyboard and role behavior follows the WAI-ARIA Authoring Practices disclosure navigation pattern. Code: `src/components/navigation-menu/`, `src/behaviors/anchored.ts`, `src/behaviors/dismiss.ts`, `hig/rules/navigation-and-search.yaml`.

Verdicts: **met**, **gap**, **deviation** (deliberate, with a reason), or **needs eyes** (a visual judgement for the maintainer). Nothing was run for this audit: no tests, no Storybook, no browser; the verdicts come from reading the source, stories and e2e files.

Components: `pl-navigation-menu`, `pl-navigation-item`.

## Library guidelines

| Guideline                                                         | Verdict    | Evidence                                                                                                                                                                                                                                                                                   |
| ----------------------------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| The current location is marked in the navigation.                 | met        | `current` sets `aria-current` (`page` on a link, `true` on a disclosure button) and draws the selected fill; a panel link carries the author's own `aria-current`. Rule navigation-and-search/1; test "the current link has aria-current page and the current section's button is marked". |
| Navigation is a named landmark.                                   | met        | A `nav` with `aria-label` from `label`; a missing label warns. Rule navigation-and-search/3; tests "the menu is a navigation landmark with the given label" and "a menu without a label logs a warning and has no aria-label".                                                             |
| (APG) Disclosure navigation, not a menu.                          | met        | Top-level buttons carry `aria-expanded` and `aria-controls`; no `role=menu`, no `aria-haspopup`. Test "it follows the disclosure pattern, not the menu pattern".                                                                                                                           |
| (APG) Tab reaches every control; Escape closes and returns focus. | met        | Every link and button is a tab stop; a panel opens without taking focus. Escape, a press outside and Tab out close it; Escape refocuses the button. Rule navigation-and-search/2; tests on Tab order, Escape and outside press.                                                            |
| One panel open at a time.                                         | met        | The menu closes the other items on `pl-toggle`. Test "opening one panel closes the other".                                                                                                                                                                                                 |
| Hit regions are at least the minimum; rows are comfortable.       | met        | Controls and panel links use `max(spacing * 8, --pl-size-hit-min)`; 44 by 44 on a coarse pointer. Test "every control and panel link is at least 44 by 44".                                                                                                                                |
| Material, contrast, forced colors, reduced motion, right-to-left. | met        | The bar and panel read the bar and panel material tokens; the panel has a real edge under forced colors; durations are zero under reduced motion; placement and the chevron follow the text direction. Tests per media feature and the rtl alignment test.                                 |
| Shallow hierarchy: one level of links per panel.                  | deviation  | Nesting is not offered: a panel holds links only. Rule navigation-and-search/4 (rubric).                                                                                                                                                                                                   |
| Arrow keys between top-level items.                               | deviation  | Not offered: APG makes them optional for disclosure navigation, and one tab stop per item keeps the pattern simple. Maintainer's call.                                                                                                                                                     |
| Narrow screens: bar wraps; collapse into a menu button.           | needs eyes | Items wrap onto further rows and the panel is limited to the viewport; there is no collapsed "menu" button. Whether a wrapping bar is acceptable on a phone is a visual call.                                                                                                              |

## Usage guidelines (for `docs/components.md`, not the component)

- Give the menu a `label` such as "Main"; a page with two navigation landmarks gives each a distinct name.
- Put the panel's links in the `panel` slot as `<a slot="panel" href>`; mark the current page with `aria-current="page"` and set `current` on the item that holds it.
- Keep labels short and the panel to one level (navigation-and-search/4, /5).
- A link item needs an `href`; an item with a panel ignores it.
