# HIG audit: text entry (input, textarea, number-field)

Source: [HIG Text fields](https://developer.apple.com/design/human-interface-guidelines/text-fields), read 2026-11-22 (change log: June 5, 2023), and [HIG Steppers](https://developer.apple.com/design/human-interface-guidelines/steppers), read 2026-11-22 (no change log on the page). Code: `src/components/input/`, `src/components/textarea/`, `src/components/number-field/`, `src/behaviors/labels.ts`, `hig/rules/text-fields.yaml`, `hig/rules/steppers.yaml`.

Each guideline is either **library** (the component decides it) or **usage** (the app author decides it, so it belongs in the docs). Verdicts: **met**, **gap**, **deviation** (deliberate, with a reason), or **needs eyes** (a visual judgement for the maintainer). Rows marked "not stated on the HIG pages" are platform behavior the pages imply; they are checked against native controls and the web platform, not against Apple's text.

The three components share one shell (`fieldStyles` in `input.css.ts`), one label and validity design and, for focus, one `delegatesFocus` host, so rows that cite `input` apply to all three unless a section says otherwise. `purr-input type="search"` is covered here only for the clear button; HIG Search fields was not read for this audit.

### Usage guidelines (for `docs/components.md`, not the component)

- Use a text field for a small amount of text such as a name or an email; use `purr-textarea` for more (text-fields/1).
- Slot a visible label in every field and add a placeholder only as a hint. `label="..."` alone gives no visible label, and the `Default` and `States` stories use it that way (`input.stories.ts:24-27`, `48-73`).
- Use `type="password"` for sensitive data (text-fields/3).
- Set `type`, `inputmode` and `autocomplete` to match the content, for example `email`, `tel`, and `autocomplete="current-password"` or `new-password` (the last is not stated on the pages).
- Size each field to its content with `inline-size`; give stacked fields consistent widths and enough space that each label clearly belongs to one field (text-fields/4, text-fields/5).
- Validate an email when the person leaves the field (built in); for a user name or password, call `setCustomValidity` and `reportValidity` before focus moves. The field shows the message below itself.
- Keep tab order the same as the visual order; the component adds no `tabindex`, so DOM order decides (text-fields/10).
- Use `purr-combobox` when text input is paired with a list of choices (text-fields/9).
- Show the full text of a clipped value some other way when it matters, such as a wider field or the value beside it (text-fields/8).
- Keep text entry short on tvOS and watchOS; not applicable to the web.

### Usage guidelines (for `docs/components.md`, not the component)

- Use a text area only for longer text; use `purr-input` for a name, an email or a short value (text-fields/1).
- Slot a visible label, and treat the placeholder as a hint only.
- Set `rows` or the height to the amount of text expected; set `resize="none"` when the layout must not change.
- Set a custom message with `setCustomValidity` when the browser's own does not say enough; the field shows it below itself.
- Add a character count or limit text yourself when `maxlength` is set; the component shows none (not stated on the pages).

### Usage guidelines (for `docs/components.md`, not the component)

- Use a stepper for small changes of one value; keep the typeable field for ranges where people may jump (steppers/2).
- Set `min`, `max` and `step` so the field can clamp and snap; page keys and Home and End depend on them.
- Slot a visible label that says which value the stepper changes (steppers/1).
- Choose `stepper="outside"` when the stepper should sit next to the field rather than inside it.
- Show units, currency or percent in the label or beside the field, because the component displays the bare number.
- Set `lang` on the field or an ancestor to change the decimal separator; the `value` property and the submitted value are always plain numbers.

## Findings outside HIG

- The accessible names "Clear", "Increase" and "Decrease" are defaults that `clear-label`, `increase-label` and `decrease-label` replace, per `design/decisions.md` item 6. Tests: `input.e2e.ts` "clear-label names the clear button" (`input.e2e.ts:151`), `number-field.e2e.ts` "increase-label and decrease-label name the stepper buttons" (`number-field.e2e.ts:58`).
- `purr-input type="number"` is a native number input (`input.ts:27`, `292`), and no rule hides the browser's own spin buttons (grep of `src` for `spin-button`: none). Whether a second stepper shows in a browser was not checked (unverified).
- A typed value that is off the step grid is snapped on commit instead of being flagged (`number-field.ts:297`); a native number input would mark it invalid.
- `inputmode="decimal"` is fixed, so an integer-only field cannot ask for the numeric keyboard (`number-field.ts:450`). Whether the iOS decimal keypad offers a minus sign for negative values is from general knowledge, not from the pages or the code (unverified).
