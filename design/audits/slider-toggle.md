# HIG audit: slider and toggle

Source: [HIG Sliders](https://developer.apple.com/design/human-interface-guidelines/sliders), read 2026-11-22 (change log: June 21, 2023); [HIG Toggles](https://developer.apple.com/design/human-interface-guidelines/toggles), read 2026-11-22 (change log: March 29, 2024), only the part on buttons that behave like toggles; and [HIG Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons), read 2026-11-22 (change log: December 16, 2025), only where it applies to the toggle button. Code: `src/components/slider/`, `src/components/toggle/`, `src/components/button/`, `src/behaviors/pressable.ts`, `src/behaviors/interaction.css.ts`, `hig/rules/sliders.yaml`, `hig/rules/toggles.yaml`, `hig/rules/buttons.yaml`.

Each guideline is either **library** (the component decides it) or **usage** (the app author decides it, so it belongs in the docs). Verdicts: **met**, **gap**, **deviation** (deliberate, with a reason), or **needs eyes** (a visual judgement for the maintainer). Rows marked "not stated on the HIG page" are platform behavior the pages imply; they are checked against native controls and the web platform, not against Apple's text. Pixel sizes are derived from `tokens.css:165-167` at 4px per spacing unit, as in the other audits.

The toggle keeps Enter as an activation key, like a native button; only checkbox, switch, radio and segmented control drop it. That is not a gap.

## Usage guidelines (for `docs/components.md`, not the component)

- Introduce a slider with a visible label in sentence-style capitalization that ends with a colon (macOS). The library's `label` names the slider for assistive technology only; a slider without it fails axe (`slider.e2e.ts:351-360`, rule sliders/5).
- Over a wide range, add a text field and a stepper beside the slider so people can see and enter an exact value (rule sliders/3). `purr-number-field` is the library's field with a stepper.
- Put the minimum on the leading side and the maximum on the trailing side; do not reverse the range for a vertical or reversed design.
- Use tick marks to show the scale. Set `ticks` to match the `step` grid yourself, for example `ticks="5" step="25"` over 0 to 100 (`slider.stories.ts:56-70`).
- Label only the ends of the scale when you add tick labels, and label more only when the values are nonlinear or the scale is unclear.
- Use end icons that show what the minimum and maximum mean, for example a small and a large image for a size slider.
- Use a horizontal slider for a value between fixed ends; the page reserves circular sliders for values that repeat (macOS).
- Give live feedback from `purr-input`, not only `purr-change`.
- Do not use a slider for audio volume on iOS or iPadOS; the page says to use a volume view there (not a web concern).

The HIG Toggles page says buttons that behave like toggles use a different appearance for each state and links to `ToggleStyle`; its detail comes from the iOS paragraphs and the Buttons page.

## Usage guidelines (for `docs/components.md`, not the component)

- Use a toggle button for two opposing values that affect the state of content or a view; for a choice from a list, use a pop-up button or select (toggles/1).
- Outside a list, use a toggle button rather than a switch (iOS and iPadOS). In a settings list row, use a `purr-switch`.
- Identify what the toggle affects through its surroundings or a label. With an icon-only toggle, pick a familiar interface icon and give it an `aria-label` (toggles/11, buttons/6, buttons/7).
- On iOS and iPadOS the page says to avoid a label that explains an icon toggle's purpose, because the icon and the state background do that job. Keep the label for a text toggle.
- Supply an outline icon for the off state; the toggle fills it with the current color when on (`toggle.css.ts:30-32`). An icon that is already solid shows no change in the glyph.
- Keep the accessible name the same in both states; the state is carried by `aria-pressed`. Do not rename the button to "Unfavorite". Not stated on the HIG page.
- Use toggle buttons in a view, not in the window frame; in a toolbar use a toolbar item (Buttons page, macOS).
- Give an icon-only toggle a tooltip that explains it; the page says macOS shows one on hover. Not part of this library.
- Use a group of buttons with one choice at a time as a `purr-toggle-group`, not several toggles.

## Findings outside HIG

- The slider's `ticks` and `step` are independent. `ticks="5"` with the default `step="1"` draws five dots that do not match any value (`slider.ts:225-237`, `slider-math.ts:13-18`); the stories set both by hand (`slider.stories.ts:56-70`).
- The slider sets no `aria-valuetext` (`slider.ts:207-223`), so a screen reader speaks the number alone; a unit such as "50 percent" is not possible. Not verified against a screen reader.
- The toggle inherits `variant`, `type` and `destructive` from `purr-button`. The docs say they have no use (`docs/components.md:705`), but they are not removed: `type="submit"` on a toggle still submits the form, because the button's `purr-press` handler runs too (`button.ts:54-58`, `toggle.ts:14-36`). Read from the code; not run.
- A toggle reuses the button (`docs/components.md:705`), so any button change also changes the toggle.
