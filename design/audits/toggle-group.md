# HIG audit: toggle-group

Source: [HIG Segmented controls](https://developer.apple.com/design/human-interface-guidelines/segmented-controls), read 2026-11-22 (change log: June 21, 2023). Code: `src/components/toggle-group/`, `src/behaviors/pressable.ts`, `src/behaviors/roving-focus.ts`, `hig/rules/segmented-controls.yaml`.

Each guideline is either **library** (the component decides it) or **usage** (the app author decides it, so it belongs in the docs). Verdicts: **met**, **gap**, **deviation** (deliberate, with a reason), or **needs eyes** (a visual judgement for the maintainer). Rows marked "not stated on the HIG page" are platform behavior the page implies; they are unverified against Apple's own controls.

## Usage guidelines (for `docs/components.md`, not the component)

- Use a segmented control for closely related choices that affect an object, state or view (segmented-controls/1).
- Choose it when grouping and a visible selected state matter (segmented-controls/2).
- Keep one control either all selection or all actions. With this library a segment only selects; for actions use buttons or a toolbar (segmented-controls/3).
- Aim for no more than about five to seven segments on a wide layout and about five on a phone (segmented-controls/4). The component does not enforce a count.
- Keep segment content a similar size so the equal columns look balanced (segmented-controls/5).
- Use text or images in one control, not both (segmented-controls/6).
- Write labels as nouns or noun phrases in title-style capitalization; a control with text labels needs no introductory text (segmented-controls/7).
- Always set `label` (or `aria-label`); the group has no accessible name otherwise (`toggle-group.ts:62-63`).
- On macOS-style layouts, consider introductory text, and a tooltip for each segment when the segments are icons.
- Switch between closely related subviews with a segmented control. For separate sections of an app use a tab bar; for the main window area use a tab view, and keep the segmented control for toolbars and inspectors.

## Findings outside HIG

- The component is single-choice only, though the HIG page allows multiple choice in macOS. A multi-select control, such as bold, italic and underline, has no component (`toggle-group.ts:89-92`).
- `design/visual-spec.md:257-283` describes a moving selection pill, 600 weight on the selected label, column width set by the widest label at weight 600, and a 28px track. The code has a per-item face with no motion, one weight, and 24px at md (`toggle-group.css.ts:25,92-106`; `tokens.css:165`). The tokens win (see below).
- The group's `purr-change` and `value` are documented, but a one-item array in `detail.selected` is a multi-select shape on a single-select control (`toggle-group.ts:71`). It matches the shared `SelectionController` event, so this is noted rather than judged.
- The first and last item radii use `:first-child` and `:last-child` (`toggle-group.css.ts:65-73`); a non-item element slotted in the group would take the corner radii. Unverified.

## Source of truth

`src/tokens/tokens.css` is the source of truth for sizes, radii, spacing and colors (decided 2026-11-22). `design/visual-spec.md` has a segmented control section (lines 257-283) and is superseded where it differs from the tokens.
