# HIG audit: sidebar (sidebar, sidebar-section, sidebar-item)

Source: [HIG Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars), read 2026-11-22 (change log: June 8, 2026). Code: `src/components/sidebar/`, `src/behaviors/roving-focus.ts`, `src/surfaces/surfaces.css.ts`, `hig/rules/sidebars.yaml`.

Each guideline is either **library** (the component decides it) or **usage** (the app author decides it, so it belongs in the docs). Verdicts: **met**, **gap**, **deviation** (deliberate, with a reason), or **needs eyes** (a visual judgement for the maintainer). Rows marked "not stated on the HIG page" are platform behavior the page implies; they are checked against native controls and the web platform, not against Apple's text. The visionOS section of the page (a sidebar inside a tab) is not covered: there is no tab bar component to nest it in.

The three elements work as one unit: `purr-sidebar` owns the toggle, the landmark, collapse and keyboard; `purr-sidebar-section` is a titled group; `purr-sidebar-item` is a row. Rows that cite `sidebar.ts` apply to all three.

## Usage guidelines (for `docs/components.md`, not the component)

- Use a sidebar for areas of the app or top-level collections such as folders and playlists. When space is tight, or content needs more room, use another navigation control; a tab bar is preferred on a phone, and the library has none, so the app supplies one.
- Extend rich content beneath the sidebar, by letting it scroll or with a background extension effect. That is layout, so the app does it.
- Let people customize the sidebar where it makes sense: which items show, and in what order. The library has no reorder feature, so the app builds it.
- Add a View menu command or a show/hide button for the sidebar, using `collapsed` and `purr-collapse`. Read the first state from `collapsed`, because the event can fire before a listener is attached.
- Keep to two levels. If the data is deeper, add a content list between the sidebar and the detail view.
- Title each group with short labels, leaving out unnecessary words.
- Use an icon only where it helps, and a fixed icon color only to give one item meaning, such as Mail's VIP star.
- Put nothing critical at the bottom of the sidebar; people move windows so the bottom edge can be hidden.
- Handle navigation yourself: the sidebar marks the selected link and fires `purr-change`, but does not change the page.

## Findings outside HIG

- The doc comment says a group "never reaches into the next section" and the code enforces it (`sidebar.ts:79-80`), but an orphaned level 2 item at the top of a section simply shows as a top-level row (test `sidebar.e2e.ts:815-829`). No warning is raised.
- An invalid `level` in production silently becomes level 2 (`level.ts:25`).
- The toggle's accessible name defaults to the sidebar `label` plus "sidebar", or "Sidebar"; `toggle-label` replaces it, per `design/decisions.md` item 6 (`sidebar.ts:9`, `223-228`). Test: `sidebar.e2e.ts` "toggle-label names the toggle button".
- `design/visual-spec.md` still lists "sidebar icon slot, group titles" as out of scope (line 9) and describes a 28px row, a weight-600 selected label and an accent `selection` face (lines 317, 337, 342). The code has the icon slot and sections, 32px rows and a `muted-3` selected face. The tokens file decides; the spec is out of date.

## Source of truth

`src/tokens/tokens.css` is the source of truth for sizes, radii, spacing and colors (decided 2026-11-22). Where `design/visual-spec.md` disagrees (sidebar row height, selected face, label weight), it is superseded.
