# HIG audit: accordion (accordion, accordion-item)

Source: [HIG Disclosure controls](https://developer.apple.com/design/human-interface-guidelines/disclosure-controls), read 2026-11-23 (no change log date on the page data). Code: `src/components/accordion/`, `src/behaviors/roving-focus.ts`, `hig/rules/disclosure-controls.yaml`. Keyboard follows the WAI-ARIA APG accordion pattern.

Each guideline is either **library** (the component decides it) or **usage** (the app author decides it, so it belongs in the docs). Verdicts: **met**, **gap**, **deviation** (deliberate, with a reason), or **needs eyes** (a visual judgement for the maintainer). Rows marked "not stated on the HIG page" are platform behavior the page implies or the APG states.

## Usage guidelines (for `docs/components.md`, not the component)

- Hide details until they are relevant; keep the most-used controls visible and advanced options closed at first (disclosure-controls/1).
- Write each heading so it says what its section shows (disclosure-controls/2).
- Keep a disclosure next to the content it controls, and use at most one standalone disclosure button per view (disclosure-controls/3). The accordion is a list of sections, not a lone button.
- Set `level` so the headings continue the page outline; the default is 3.
- Give each item a `value` so `pl-toggle` identifies it.

## Findings outside HIG

- In single mode, the items that close because another opened fire no `pl-toggle`; only the item the person used does. An app that tracks state reads the opened item and treats the rest as closed.
- Programmatic `open` on an item also closes the others in single mode, silently.
- No `collapsible` option for single mode: the open section can always be closed (the APG treats a non-collapsible open section as optional).
- Native find-in-page does not open a closed section (`hidden="until-found"` is not used because the height animation needs the panel rendered).
