# HIG audit: combobox

Source: [HIG Combo boxes](https://developer.apple.com/design/human-interface-guidelines/combo-boxes), read 2026-11-22 (no change log on the page). Code: `src/components/combobox/`, `src/components/select/` (`match.ts`, `popup.ts`, `select.css.ts`, the shared `purr-option`), `src/components/input/input.css.ts`, `src/behaviors/dismiss.ts`, `hig/rules/combo-boxes.yaml`. HIG Pull-down buttons and Text fields, which the page links to, were not read for this audit; the text-fields rows lean on the text-fields audit.

Each guideline is either **library** (the component decides it) or **usage** (the app author decides it, so it belongs in the docs). Verdicts: **met**, **gap**, **deviation** (deliberate, with a reason), or **needs eyes** (a visual judgement for the maintainer). Rows marked "not stated on the HIG page" are platform behavior the page implies; they are checked against native controls and the web platform, not against Apple's text. Nothing was run for this audit, so every verdict comes from reading the code and the existing tests.

The page is short: a combo box combines a text field with a pull-down button; people type a custom value or pick from a list, and a typed value is not added to the list. It is macOS only (not supported in iOS, iPadOS, tvOS, visionOS or watchOS).

## Usage guidelines (for `docs/components.md`, not the component)

- Choose a combo box when people may type a value that is not in the list. Without `allow-custom` it behaves as a filterable choice from the list, and unmatched text is discarded on leaving.
- Add a visible introductory label with `slot="label"`, in title-style capitalization and ending with a colon. `label="..."` alone draws nothing and only names the field for assistive technology.
- Start with a meaningful default from the list: set `value`, or mark an option `selected`. It need not be the first item. Leave the field empty only when no default fits (combo-boxes/1).
- Offer relevant choices: the list the people most likely want, not every possible value (combo-boxes/4).
- Keep option labels no wider than the field, or give the field an `inline-size` wide enough for the longest label, so a chosen label is not clipped (combo-boxes/5; see the gap above).
- Set `allow-custom` for a field that takes a free value, and read `value` for the text; the custom value is not added to the options, so add it yourself if you want it listed next time.
- Not available on iOS, iPadOS, tvOS, visionOS or watchOS per the page; the library runs on every web platform regardless, so this is a note for app authors targeting Apple platforms.
- Put validation messages in the page beside the field; `required` marks the form invalid until there is a value, and the component draws no message (see the text-fields audit).

## Findings outside HIG

- Rule combo-boxes/5 says "The list is at least as wide as the field, so no choice is clipped by it", and its test checks that. The page says list items should not be wider than the text field, because the field may truncate a chosen item. These are different properties. The code satisfies the rule and not the page wording; the rule text should be reconciled with the page before the row above is closed.
- Built-in strings are localizable, per `design/decisions.md` item 6: `empty-label` replaces "No results" and `toggle-label` the chevron's name, and the `required` message is the browser's own (`nativeMessage`). Test: `combobox.e2e.ts` "toggle-label and empty-label replace the built-in strings".
- `docs/components.md` lists the private `_active` state as an attribute (line 123) and an empty `name:` event (line 139) in the combobox section. Both look like output of the docs generator reading `@fires` and `static properties`; not checked further.
- `purr-option` is documented as "One choice in a `purr-select`" and "does nothing alone" (`select.ts:10-11`), but the combobox uses it too; the combobox sets `data-active` and `chosen` on it from outside (`combobox.ts:315-318`). Not an HIG matter.
- Typing narrows the list only after an edit, so opening with the chevron shows every option even when the field holds a chosen label (`combobox.ts:95-97`, e2e `combobox.e2e.ts:162`). Not stated on the page; whether native macOS does the same was not checked (unverified).
