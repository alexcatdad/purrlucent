# HIG audit: select (pop-up button)

Source: [HIG Pop-up buttons](https://developer.apple.com/design/human-interface-guidelines/pop-up-buttons), read 2026-11-22 (change log: October 24, 2023), and [HIG Pickers](https://developer.apple.com/design/human-interface-guidelines/pickers), read 2026-11-22 (change log: June 5, 2023). Code: `src/components/select/`, `src/behaviors/dismiss.ts`, `src/behaviors/position.ts`, `hig/rules/pop-up-buttons.yaml`.

Each guideline is either **library** (the component decides it) or **usage** (the app author decides it, so it belongs in the docs). Verdicts: **met**, **gap**, **deviation** (deliberate, with a reason), or **needs eyes** (a visual judgement for the maintainer). Rows marked "not stated on the HIG pages" are platform behavior the pages imply; they are checked against native controls and the web platform, not against Apple's text.

`purr-select` is the library's pop-up button: a trigger that shows the chosen option and a popup list of `purr-option` children. Of the Pickers page, only the best-practice guidance on lists applies. The date picker styles, wheels, and the iOS, macOS, tvOS and watchOS sections describe controls the library does not have. `purr-menu` is the library's pull-down button and is not covered here.

## Usage guidelines (for `docs/components.md`, not the component)

- Use a select for a flat list of mutually exclusive options or states. For actions, multiple selection or a submenu, use `purr-menu` (pop-up buttons/1).
- Give every select a visible label (`slot="label"`) or surrounding text that says what the options affect. `label="..."` alone draws nothing and only names the control for assistive technology (pop-up buttons/3).
- Always give a default: mark the most likely option `selected`, or set `placeholder`. With neither, the trigger is blank (pop-up buttons/2).
- Choose a select when space is tight and not every option needs to be seen at once. When there are only a few options and room, show them (a `purr-toggle-group` or `purr-radio-group`) (pop-up buttons/4).
- For a short list consider a menu instead; for a very large set consider a list or table, or `purr-combobox` when people should type to narrow it (Pickers page, best practices).
- Order the options predictably, such as an alphabetized list of countries, because most are hidden until the list opens (Pickers page).
- Put a rarely needed set of extra choices behind a Custom option, with explanatory text below the list if it helps, instead of adding controls to the page (pop-up buttons/5). The component has no slot for text below the list.
- In a popover or modal view on iPadOS, a pop-up button can replace a disclosure indicator for a small, well-defined set of options. Not applicable to the web as a platform rule; it holds as a layout choice.
- Date and time pickers, wheels and the watchOS Digital Crown are not provided by this library.

## Findings outside HIG

- The `required` validation message is the browser's own, localized one, borrowed from a native select (`nativeMessage`, `src/behaviors/native-message.ts`), per `design/decisions.md` item 6.
- The only change event is `purr-change` (`select.ts:185-191`); no native `change` or `input` event is dispatched, so code written for a native `<select>` does not hear a choice.
- `listboxStyles` is shared by "every component that lists options under a field" (`select.css.ts:136`), so a change to the popup here also changes those components.

## Source of truth

`src/tokens/tokens.css` is the source of truth for sizes, radii, spacing and colors (decided 2026-11-22). `design/visual-spec.md` has no section on the select or pop-up button (grep for "select" finds only the selection color and segmented control rows) and is superseded where it differs from the tokens.
