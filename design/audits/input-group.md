# HIG audit: input group

Source: [HIG Text fields](https://developer.apple.com/design/human-interface-guidelines/text-fields), read 2026-11-22 (change log: June 5, 2023). Code: `src/components/input-group/`, `src/components/input/input.css.ts` (the `data-grouped` rules), `hig/rules/text-fields.yaml`. The text-entry audit in `design/audits/text-fields.md` records leading and trailing content as a deviation of `pl-input`; this component supplies it.

Verdicts: **met**, **gap**, **deviation** (deliberate, with a reason), or **needs eyes** (a visual judgement for the maintainer). Rows marked "not stated on the HIG page" are platform behavior checked against native controls and the web platform.

## Usage guidelines (for `docs/components.md`, not the component)

- Name the field with the input's own label; an addon is not its name. Give a text addon that carries meaning, such as a unit, an `id` and list it in the input's `aria-describedby`.
- Mark an svg icon addon `aria-hidden="true"`; an icon-only `pl-button` addon needs an `aria-label`.
- Put one `pl-input` or `pl-textarea` in a group, with at most one addon on each side. Text and icons are not focusable; a `pl-button` is a tab stop before or after the field.
- Size the group, not the input, with `inline-size`; the input fills what the addons leave.
- Use `pl-input` and `pl-textarea` `size` for the height; the group follows it.

## Findings outside HIG

- The group measures the input's `[part="field"]` with a resize observer and sets `--_top` and `--_h` on itself, so the shell lines up below a label and above a message. These are measured layout values, not design values.
- `pl-input`, `pl-textarea` and `pl-number-field` share `fieldStyles`; the `data-grouped` attribute the group sets turns the shell's own edge, fill and ring off. `pl-number-field` is not supported as a group child.
- `:host(:has(> :state(user-invalid)))` and `:host(:has(> :disabled))` follow the input without events. Browsers without `:has()` inside `:host()` lose the invalid and disabled shell looks (unverified).
- `aria-description` is ARIA 1.3; assistive technology support was not checked (unverified). The input's own `aria-describedby` on the control is untouched, so its validation message is still announced.
