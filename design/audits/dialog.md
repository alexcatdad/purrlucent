# HIG audit: dialog (alerts and sheets)

Source: [HIG Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts), read 2026-11-22 (change log: February 2, 2024), and [HIG Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets), read 2026-11-22 (change log: March 24, 2026). Code: `src/components/dialog/` (`variant="alert"` and `variant="sheet"` of `purr-dialog`), `src/components/button/button.ts`, `src/behaviors/pressable.ts`, `hig/rules/alerts.yaml`, `hig/rules/sheets.yaml`. The dialog uses no shared behavior of its own: `src/behaviors/dismiss.ts` is not imported; the native `<dialog>` gives Escape, the inert page and the focus trap.

Each guideline is either **library** (the component decides it) or **usage** (the app author decides it, so it belongs in the docs). Verdicts: **met**, **gap**, **deviation** (deliberate, with a reason), or **needs eyes** (a visual judgement for the maintainer). Rows marked "not stated on the HIG pages" are platform behavior the pages imply; they are checked against native macOS dialogs and the web platform, not against Apple's text. The Sheets page's March 24, 2026 entry says button placement guidance was updated; the text read states placement for iOS and iPadOS only (Cancel leading, Done trailing in the top toolbar). Placement in macOS sheets may be in artwork that did not render; it is not verified here.

## Usage guidelines (for `docs/components.md`, not the component)

- Use an alert sparingly, for critical information the person needs right away; do not use one merely to inform, and prefer showing information in context (alerts/1, alerts/2).
- Do not alert for common, undoable actions, even destructive ones. Alert for an uncommon destructive action that cannot be undone (alerts/3).
- Do not show an alert at app start; show cached or placeholder data with a quiet note instead (alerts/4).
- Write a title that says what happened and why, direct and neutral, never just "Error" and no longer than two lines. A full-sentence title takes sentence-style capitalization and ending punctuation; a fragment takes title-style capitalization and none. Add a message only if it adds value, in complete sentences (alerts/5).
- Button titles are one or two verbs that name the result; use Cancel to cancel. Use OK only in a purely informational alert, never Yes or No. Do not explain what the buttons do; if you must, say "choose" and use the button's exact title (alerts/6, alerts/7).
- Give an alert with a destructive action a Cancel button marked `cancel`. Never mark Cancel `default`; to make people read, mark no button `default`. A single default button is Done, not Cancel (alerts/9).
- Apply the `destructive` attribute only to a destructive action the person did not choose on purpose. When they chose it (Empty Trash), the confirming button is not destructive (alerts/8).
- Order the actions yourself: the default button trailing in a row or first in a stack, Cancel leading or last. The dialog keeps source order. Use at most three buttons (alerts/11).
- A text field belongs in an alert only when the answer is needed to resolve it, such as a password. Use a caution symbol sparingly, not for a save or empty-trash confirmation.
- Use a sheet for a scoped task tied to the current context, such as a file name or a choice. Long or multi-step tasks belong on a page or in a window; supplementary content that affects the main task belongs in a nonmodal panel (sheets/1, sheets/7, sheets/8).
- Show one sheet at a time. When a sheet leads to another, close the first, then open the second, and reopen the first afterward if needed (sheets/6).
- Pair a Done button with Cancel, or with Back in a multi-step flow; never show Cancel, Done and Back together. The library supplies no buttons, so set `data-close` on each (sheets/4, sheets/5).
- Mark the default and cancel actions with `default` and `cancel`. Set `autofocus` only on a field that should have focus on open.
- Set `dismissible` on a sheet only when pressing outside may discard its state, and handle `purr-cancel` to confirm when there are unsaved changes.

## Findings outside HIG

- The `OpenAlertWithIcon` story (`dialog.stories.ts:164-182`) lists Delete, a destructive action, first and Cancel trailing, which contradicts the Alerts page's placement. Cancel is marked `cancel`, so it takes initial focus and Delete does not.
- `#focusInitial` finds `[autofocus]` with `this.querySelector` (`dialog.ts:194`), so an `autofocus` element inside another component's shadow root is not found and focus falls back to the first action.
- The scroll lock sets `overflow: hidden` on `document.documentElement` (`dialog.ts:13-18`), which removes a classic scrollbar and can shift the page by its width. Not checked in a browser.
- The generated reference in `docs/components.md:159-160` lists the private `_scrolls` and `_actions` states as attributes.
- Not checked here: the stories in a browser, and any visual comparison to a native macOS alert or sheet. All "needs eyes" rows are unverified.
